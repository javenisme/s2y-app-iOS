# 选择性跨设备同步

H32 / US-303 让用户按数据类别决定是否跨设备同步。所有类别默认关闭，启用和撤回都有版本化本地收据。

## 数据边界

| 类别 | 云端路径 | 内容 |
|---|---|---|
| 对话 | Omer，使用 Firebase ID Token 认证 | 用户明确允许的端侧对话副本；在线 Omer 对话沿用现有服务端记录 |
| 应用偏好 | Firebase Firestore | AI 提供者选择，以及语音开关、语言和语速 |
| 健康管理计划 | Firebase Firestore | 用户创建或确认的计划、行动、目标和删除墓碑 |

不会同步 HealthKit 原始样本、HealthKit 权限状态、分享同意收据、API 密钥、Token、服务端点、设备会话审计或本地健康摘要文件。应用偏好使用固定允许列表，未知键或类型不匹配的数据会被拒绝。

## 合并与撤回

- 同一记录先比较修改时间，再比较设备 ID；仍相同时删除优先，最后比较规范化 JSON，保证不同设备得到相同结果。
- 健康计划删除会保留墓碑，避免离线旧设备把已删除计划重新带回。
- 开启对话同步后，会尝试补传本地尚未同步、且满足独立对话分享授权的端侧对话。
- 关闭某一类别会立即停止该类别后续同步，但不会暗中删除既有云端副本；云端删除仍通过账户数据删除流程显式执行。
- 网络不可用或未登录时保留本地数据，并在设置页展示真实状态和重试入口，不把失败伪装成已完成。

## 云端约束

Firestore 文档位于 `users/{uid}/sync/{category}`。规则要求请求者是文档所有者，只允许 `appPreferences` 和 `wellnessPlans` 两个类别，限制字段集合、Schema 版本、载荷大小和设备标识长度。客户端还会限制编码后载荷大小、未来时间、计划字段数量与长度，并拒绝畸形记录。

## 验证边界

单元测试覆盖默认关闭、版本化选择、确定性冲突、删除墓碑、允许列表、类型校验和计划身份校验；模拟器构建验证界面与协调器集成。生产发布前仍需两个登录同一测试账号的设备，在真实 Firestore/Omer 环境中验证离线恢复、撤回后停止新增和账户数据删除。客户端测试不能替代生产规则部署与服务端日志证据。
