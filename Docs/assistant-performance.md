# Health Assistant 性能、取消与缓存边界

## 已实现事实

- Apple Foundation Models 使用系统 `streamResponse` 快照，首个快照即首响应时间。
- Omer 当前 `/api/mobile/v1/chat` 返回一次性 JSON；客户端可取消等待中的网络任务，但不把整段答案伪装为逐 token 流。
- 输入区在生成期间提供停止按钮。取消沿 Swift 并发任务传播到 Apple 流或 `URLSession`。
- Apple 与 Omer 分开记录完成、取消和失败结果；完成样本按 nearest-rank 计算 P95。
- 性能事件只含提供者、结果、首响应/总毫秒数及是否使用健康上下文，不含提示词、回答、用户标识、会话标识或健康数值。
- 性能事件只保留本进程最近 50 条，不上传、不持久化。

## HealthKit 缓存边界

- 日指标、趋势和相邻窗口比较缓存于内存，默认五分钟过期。
- 趋势和比较键按本地日边界归一化，避免同一天因调用时刻不同而失去复用。
- 缓存公开进程内的命中、未命中、过期和失效计数，不记录缓存值。
- 清除本地健康数据会清空缓存；蓝牙数据成功写入 HealthKit 后，只失效该载荷影响的指标。
- 缓存不是健康数据的权威来源；进程结束即消失，用户请求刷新时可绕过。

## 尚需外部验证

- 合资格 iPhone 上 Apple 首响应和总时延预算、取消响应速度及多轮稳定性属于 US-202/H28。
- Omer 若未来提供 SSE/WebSocket/分块传输，必须新增明确协议和测试后才能宣称在线逐 token 流式。
- 生产 P95 目标值需要在不上传敏感内容的观测方案和发布样本量确定后冻结；当前实现提供本地基线计算能力，不代表生产 SLA 已达成。
