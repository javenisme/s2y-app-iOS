# S2Y iOS 可验证路线图

路线图以“什么证据能证明完成”为中心。代码合并、外部环境和真实设备是不同门槛，
不得相互替代。

## 当前基线

- H01～H27 已合并到 `main`；H30 已在主题分支实现并等待验证与 PR。
- 支持的 AI 只有用户显式选择的 Apple 端侧 AI 和 Omer 在线 AI。
- 下载式 Phi/MLX 模型、模拟回答、固定人群阈值、自动健康目标和临床风险评分已退休。
- 当前闭环是健康管理闭环，不是诊断或治疗闭环。

## Gate 1：工程质量

每个 iOS Epic 合并前必须提供：

1. 一个故事一个提交，提交标题包含唯一 HLT 编号；
2. 一个主题一个 PR；
3. iOS Simulator 应用编译通过；
4. 改动相关专项测试通过；
5. 完整 `S2YTests` 通过；
6. 未通过的 CI 必须区分代码失败、外部服务失败和工具链失败；
7. 不提交密钥、生产 token、个人健康数据或本地品牌素材草稿。

## Gate 2：生产服务

H25 / US-201、US-204 的完成证据：

- Firebase Google 登录从 `www.s2y.us` 发起并成功返回；
- Firebase ID Token 在 `chat.s2y.us` 校验成功；
- Omer 对话、用量账本、订阅权限和用户数据范围可由测试账号验证；
- 云端健康数据只有在相应独立同意范围内出现；撤回后停止新增；
- Production 与 Preview 环境变量分离，不依赖 `chat-bak.s2y.us`；
- iOS Archive、签名、TestFlight 安装、启动和回滚演练完成。

## Gate 3：合资格 iPhone

H28 / US-202 的完成证据：

- Apple Foundation Models 可用状态在支持机型上正确；
- 端侧回答确实由系统模型生成，网络关闭时仍可工作；
- 首 token、总时延、取消与多轮上下文达到定义的预算；
- HealthKit 访问仍受本地权限约束；端侧对话同步另行同意；
- 不支持机型展示诚实、可恢复的不可用状态。

## Gate 4：真实 S2Y 设备

H29 / US-203 的完成证据：

- 设备身份、固件签名、协议版本和能力握手均被验证；
- 未验证设备不能启动会话；
- 用户确认后才能开始，用户停止和断连停止均在本地生效；
- 会话限制不能由 Omer 或网络响应绕过；
- 审计不保存聊天正文或不必要的健康详情；
- UI 与文档只使用健康管理/舒适度措辞，不宣称治疗效果。

## 近期实施顺序

## 完成与不完成

以下情况不能标记 Epic 完成：

- 只有代码搜索没有运行验证；
- 只有模拟器结果却声称真机 AI 或 HealthKit 成功；
- 只有客户端单元测试却声称生产 Firebase/Omer 成功；
- 只有 mock 蓝牙设备却声称真实 taVNS 闭环成功；
- CI 尚未结束或失败原因未分类；
- 验收标准仍依赖未记录的人工操作。
