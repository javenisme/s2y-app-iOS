# S2Y iOS 可验证路线图

路线图以“什么证据能证明完成”为中心。代码合并、外部环境和真实设备是不同门槛，
不得相互替代。

## 当前基线

- H01～H27、H30～H40 已合并或在当前主题完成；付费订阅映射、生产账号同意生命周期、签名真机和真实设备证据仍须继续验收。
- 支持的 AI 只有用户显式选择的 Apple 端侧 AI 和 Omer 在线 AI。
- 下载式 Phi/MLX 模型、模拟回答、固定人群阈值、自动健康目标和临床风险评分已退休。
- 当前闭环是健康管理闭环，不是诊断或治疗闭环。

## Gate 1：工程质量

每个 iOS Epic 合并前必须提供：

1. 一个故事一个提交，提交标题包含唯一 HLT 编号；
2. 一个主题一个 PR；
3. iOS Simulator 应用编译通过；
4. 改动相关专项测试通过；
5. 完整 `S2YTests` 通过；
6. 未通过的 CI 必须区分代码失败、外部服务失败和工具链失败；
7. 不提交密钥、生产 token、个人健康数据或本地品牌素材草稿。

## Gate 2：生产服务

H25 / US-201、US-204 的完成证据：

- Firebase Google 登录从 `www.s2y.us` 发起并成功返回；
- Firebase ID Token 在 `chat.s2y.us` 校验成功；
- Omer 对话、用量账本、订阅权限和用户数据范围可由测试账号验证；
- 云端健康数据只有在相应独立同意范围内出现；撤回后停止新增；
- Production 与 Preview 环境变量分离，不依赖 `chat-bak.s2y.us`；
- iOS Archive、签名、TestFlight 安装、启动和回滚演练完成。

## Gate 3：合资格 iPhone

H28 / US-202 的完成证据：

- Apple Foundation Models 可用状态在支持机型上正确；
- 端侧回答确实由系统模型生成，网络关闭时仍可工作；
- 首 token、总时延、取消与多轮上下文达到定义的预算；
- HealthKit 访问仍受本地权限约束；端侧对话同步另行同意；
- 不支持机型展示诚实、可恢复的不可用状态。

## Gate 4：真实 S2Y 设备

H29 / US-203 的完成证据：

- 设备身份、固件签名、协议版本和能力握手均被验证；
- 未验证设备不能启动会话；
- 用户确认后才能开始，用户停止和断连停止均在本地生效；
- 会话限制不能由 Omer 或网络响应绕过；
- 审计不保存聊天正文或不必要的健康详情；
- UI 与文档只使用健康管理/舒适度措辞，不宣称治疗效果。

## 近期实施顺序

### 1. 生产外部验收（P0）

仓库预检与公开端点 smoke check 已交付；继续使用生产测试账号完成 Firebase/Omer
认证证据，并完成签名、TestFlight 安装和回滚。不能在代码中伪造通过。

当前已确认已配对且开启 Developer Mode 的 iPhone 16e（iOS 26.6）具备 Apple
Intelligence 硬件资格，但 Debug 真机构建与签名 Archive 均已验证阻塞在 Xcode 账户
凭据和 Verifiable Health Records profile 能力，详见
[`release-validation.md`](release-validation.md)。不得通过删除临床记录 entitlement 绕过。

Omer 最新 `main` 已部署到 Production；已认证的新消息、AI 回复、刷新后读取、Free
订阅状态接口及用量聚合增长已验证。OMR-017～018 已增加版本化、分范围且可重试的
同意回执，并在新版 iOS 请求写入聊天或端侧会话前执行服务端授权门；完整回执快照可在
长期离线后恢复当前状态。为兼容已发布客户端，未携带策略版本的旧请求暂未强制；生产
测试账号的逐范围 grant/revoke 与删除证据仍待验收。未直接读取数据库明细，付费订阅
映射也仍须验证。Home PR #25、#26 也已正常合并并部署：公开首页、多语言入口、
Omer、StVNS、企业、移动端、HOCl、使命、案例和高风险文章均已收敛到健康教育、
用户控制和产品信息边界；14 篇旧健康/设备宣称文章已设为草稿，不能把生产文案整改
误当作运行时计费或同意证据。

客户端已实现按类别选择、可撤回且冲突确定的跨设备同步。仍须在生产 Firebase/Omer 与两个登录同一测试账号的设备上完成离线恢复、撤回和删除边界验收。

### 4. H33 临床文档生产边界验收（P3）

客户端已实现显式文件导入、本地解析与索引、片段引用和彻底删除；回答保持非诊断、可追溯。生产 Omer 仍须验证片段最小化、撤回后停止新增及账户删除边界。

## 完成与不完成

以下情况不能标记 Epic 完成：

- 只有代码搜索没有运行验证；
- 只有模拟器结果却声称真机 AI 或 HealthKit 成功；
- 只有客户端单元测试却声称生产 Firebase/Omer 成功；
- 只有 mock 蓝牙设备却声称真实 taVNS 闭环成功；
- CI 尚未结束或失败原因未分类；
- 验收标准仍依赖未记录的人工操作。
